# Internal Windows Inventory - Laravel 10 Port

This Laravel app is the central portal, importer, database application, and control plane for the existing Windows inventory architecture.

The Windows runner and branch collector remain outside Laravel:

- `../runner` stays responsible for local Windows hardware collection and scheduled-task execution.
- `../collector` stays responsible for branch-share relay, outbound central authentication, command pull, and acknowledgement forwarding.
- Laravel stores authoritative inventory state, scan history, raw-file evidence, runner health, collector health, and command queue state.

## Local Setup

The app is pinned to Laravel 10 through `composer.json`.

```powershell
cd d:\xampp\htdocs\inventaris\laravel
composer dump-autoload --no-scripts
php artisan --version
```

Default local database settings use SQLite:

```dotenv
DB_CONNECTION=sqlite
DB_DATABASE=database/database.sqlite
```

Create the SQLite file before running migrations:

```powershell
New-Item -ItemType File -Force database\database.sqlite
php artisan migrate
php artisan db:seed
```

The current CLI has `pdo_sqlite` available. If another machine reports `could not find driver`, enable `pdo_sqlite` in the PHP CLI configuration or switch `.env` to a working MySQL database.

## Admin Login

The admin portal is protected by Laravel session authentication. Configure a first local admin in `.env`:

```dotenv
INVENTORY_ADMIN_NAME="Inventory Admin"
INVENTORY_ADMIN_EMAIL=admin@example.local
INVENTORY_ADMIN_PASSWORD=password
```

Then seed:

```powershell
php artisan db:seed
```

Login at `/login`. Collector/API endpoints still use the site-token boundary and do not use browser session auth.

## Security Boundary

Clients must not contain central database credentials, Google Drive credentials, a central master secret, or shared global upload token.

Collectors authenticate outward to Laravel with `X-Site-Id` and `X-Site-Token`. Tokens are read from:

- `INVENTORY_SITE_TOKENS_JSON`, or
- `INVENTORY_SITE_TOKENS_FILE`, defaulting to `storage/app/inventory/site_tokens.json`

Local development can leave site tokens unconfigured. For pilot or production, require a configured site-token map:

```dotenv
INVENTORY_REQUIRE_SITE_TOKENS=true
```

Useful token commands:

```powershell
php artisan inventory:register-site-token SITE-HQ
php artisan inventory:site-tokens
```

`inventory:site-tokens` masks token values by default so operators can verify configured site IDs without exposing secrets.

Optional central direct intake can use:

```dotenv
INVENTORY_CENTRAL_INTAKE_TOKEN=
```

Security validation is covered by tests for:

- invalid collector site token rejection
- valid collector site token acceptance
- required site-token map enforcement
- direct central CSV intake token enforcement

## Validation Commands

Check application readiness before a pilot:

```powershell
php artisan inventory:doctor
```

Check strict deployment readiness before pilot or cutover:

```powershell
php artisan inventory:doctor --production
```

Check collector API connectivity and token authentication before installing a real collector:

```powershell
php artisan inventory:collector-diagnostic https://inventory.example.local SITE-HQ <site-token>
```

This diagnostic calls:

- `GET /health`
- `POST /api/collector/status`
- `POST /api/collector/heartbeat`
- `GET /api/collector/commands`

It creates or updates a diagnostic collector and runner record, but it does not upload inventory CSV files or acknowledge real commands.

Validate the site-kit profile before generating a deployment package:

```powershell
php artisan inventory:validate-site-profile deployment/profiles/site_hq.sample.json
```

Prepare a generated pilot profile from a sample profile and the registered site token:

```powershell
php artisan inventory:prepare-site-profile deployment/profiles/site_hq.sample.json --server-base-url=https://inventory.example.local
```

By default this writes to `deployment/profiles/generated/SITE-HQ.json`. You can override the destination:

```powershell
php artisan inventory:prepare-site-profile deployment/profiles/site_hq.sample.json --output=deployment/profiles/site_hq.pilot.json --server-base-url=https://inventory.example.local
```

After replacing placeholder tokens and URLs with real pilot values, use strict validation on the generated profile:

```powershell
php artisan inventory:validate-site-profile deployment/profiles/generated/SITE-HQ.json --strict
```

Build the final pilot site kit in strict mode so warning-level issues block package generation:

```powershell
php artisan inventory:build-site-kit --profile=deployment/profiles/generated/SITE-HQ.json --strict
```

The generated site kit includes branch-friendly launchers:

- `READ_ME_FIRST_FOR_BRANCH.txt`
- `START_HERE_INSTALL_COLLECTOR_PC.cmd`
- `INSTALL_THIS_PC_RUNNER_ONLY.cmd`
- `INSTALL_COLLECTOR_ONLY.cmd`

Branch staff should extract the ZIP first, then right-click the appropriate `.cmd` file and choose **Run as administrator**. The installer writes `install-site-kit.log` in the extracted folder.

Expected local warnings:

- missing site-token map until real tokens are registered, unless `INVENTORY_REQUIRE_SITE_TOKENS=true`
- `APP_DEBUG=true` while developing locally
- local `APP_URL` while using `php artisan serve`

Health endpoint for uptime checks:

```text
GET /health
```

Compare high-level parity with the existing Flask SQLite database:

```powershell
php artisan inventory:compare-legacy ..\data\inventory.db
```

Simulate one collector cycle locally without a Windows branch share:

```powershell
php artisan inventory:simulate-collector ..\sample_data\sample_scan_1.csv --queue-scan --ack
```

Create a local backup of the current database and raw evidence archive:

```powershell
php artisan inventory:backup --label=pre-cutover
```

SQLite backups include:

- `database.sqlite`
- `raw_archive.zip`
- `site_tokens.json` when `INVENTORY_SITE_TOKENS_FILE` points to a file
- `downloads.zip` when `--include-downloads` is used
- `manifest.json` with row counts

For MySQL/PostgreSQL, use native database dump tooling for the DB and keep this command for manifest/raw archive backup unless a DB-specific dump adapter is added.

Backup pruning and generated site-kit backup:

```powershell
php artisan inventory:backup --label=scheduled --include-downloads --prune-days=30
```

Laravel scheduler support is configurable:

```dotenv
INVENTORY_BACKUP_SCHEDULE_ENABLED=true
INVENTORY_BACKUP_SCHEDULE_TIME=01:30
INVENTORY_BACKUP_RETENTION_DAYS=30
INVENTORY_BACKUP_INCLUDE_DOWNLOADS=true
```

On Windows/XAMPP, run Laravel's scheduler from Windows Task Scheduler once per minute:

```powershell
Set-Location D:\xampp\htdocs\inventaris\laravel
php artisan schedule:run
```

Expected simulation behavior:

- collector status is upserted
- runner heartbeat/status is upserted
- CSV is ingested through the collector metadata path
- optional `scan_now` command is queued
- pending command is marked dispatched
- optional acknowledgement marks it completed

## Cutover Checklist

Use `deployment/DEPLOYMENT_CHECKLIST.md` for the detailed pilot and production checklist.

1. Back up the legacy Flask SQLite database and `data/raw_archive`.
2. Back up Laravel with `inventory:backup --label=pre-cutover` before each cutover rehearsal.
3. Run `php artisan migrate:fresh --force` only on a new empty Laravel database, never on production data.
4. Import historical CSV batches into Laravel with `inventory:import-folder`.
5. Run `inventory:compare-legacy` and review deltas.
6. Register real site tokens with `inventory:register-site-token`.
7. Set `INVENTORY_REQUIRE_SITE_TOKENS=true`.
8. Run `inventory:doctor` and resolve hard failures.
9. Generate a Laravel site kit for one pilot site.
10. Update the pilot collector config so `server_base_url` points at Laravel.
11. Confirm `/health`, collector status, runner heartbeat, CSV intake, command polling, and command acknowledgement.
12. Confirm admin reports and CSV exports show expected data.
13. Freeze Flask writes, perform final import/compare/backup, then switch the central portal URL.
